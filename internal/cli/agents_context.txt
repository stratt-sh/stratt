stratt — agent orientation
==========================

WHAT IT IS
  stratt gives every repo one set of commands — build, test, lint,
  release, deploy — that work the same whatever the language. Stratt
  detects the toolchain and dispatches, replacing the per-repo Makefile.
  Learn it once; it works everywhere.

THE ONE RULE
  Prefer stratt's verbs over the underlying tool. Run `stratt test`, not
  `pytest`; `stratt build`, not `cargo build`. Behavior stays consistent
  across every repo that uses stratt, and stratt picks the right backend.

THE VERBS
  build     compile / produce artifacts
  test      run the test suite
  lint      static checks (add --check for CI: `stratt lint --check`)
  format    apply formatting
  style     format + lint together
  release   patch | minor | major — bump version, commit, tag, push
  deploy    kustomize image bump for Kubernetes
  setup     first-time project setup
  reset     clean + setup: wipe and rebuild the dev environment
  sync      install dependencies from the lockfile (alias: install)
  lock      update the lockfile from the manifest
  upgrade   upgrade dependencies to latest compatible versions
  all       run the full verification suite (sync, format, lint, test, docs)
  run <t>   run a user-defined task from stratt.toml

DRIVING IT NON-INTERACTIVELY (for agents)
  --ci         no prompts; fail loudly on missing decisions
  -y / --yes   skip confirmations
  -q           quiet output
  --no-push    (release) commit and tag locally without pushing
  --no-commit  (release) write the bump only; no commit/tag/push
  Exit codes:  0 ok · 130 interrupted · non-zero on any other error

SEE WHAT RUNS HERE
  `stratt doctor` shows the resolved backend for each verb in this repo,
  plus detected stacks and missing tools. The resolved map for the current
  repo is printed below.
